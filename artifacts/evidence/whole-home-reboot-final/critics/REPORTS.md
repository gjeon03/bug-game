## Korean UX critic (native speaker) — **FAIL**

The catalog is genuinely well-written Korean — tense, idiomatic, consistent 해라체, correct keep-all line breaking, zero tofu at all four tested viewports, zero missing keys, and no player-facing English anywhere. The author's own §4a rule ("particles are computed, never hardcoded") is the thing the build violates: four keys hardcode the written-form fallback `(으)로`, and it renders literally on screen. `음식물 쓰레기통(으)로 가는 페로몬 길을 놓았다.` is visible in three of the six final evidence screenshots (05, 06, 07) and is the FIRST Korean sentence the game ever writes — every route, every gate, every alert escalation. That alone is a ship blocker. Underneath it, a second grammar class fails: `log.threat.incoming` renders `주방에 불이 켜짐이 온다.` and `주방에 행주질이 온다.` for 4 of 7 threats. And structurally, 51 authored player-facing keys — including all 7 route-diagnostic strings, the WebGL2 error, the loading screen, and the adaptation cost — are never rendered by any code path. The author's claim that untranslated text is "structurally impossible" (hud.ts:12-15) is true for *missing* translation and false for *wrong* Korean, and there is not one i18n test in the repo to catch either.

### [BLOCKER] `(으)로` renders literally on screen — the game's first Korean sentence is broken
- **evidence:** src/i18n/ko.ts:169, 224, 231, 236 hardcode the written-form fallback `(으)로`. Rendered through the real t(): `음식물 쓰레기통(으)로 가는 페로몬 길을 놓았다.` / `거실(으)로 가는 길이 열렸다.` / `거실 경계 단계가 경계(으)로 올라갔다.` / `싱크대 밑 공간(으)로 들어가는 보급선이 끊겨 있다`. Visible on screen in artifacts/evidence/whole-home-reboot-final/05-colony-working.png (bottom right, lines 1 and 3), 06-1280x720.png and 07-1440x900.png.
- **why it costs the player:** log.route.laid fires the moment the player draws their first pheromone route — inside the first ~20 seconds of every run, and again on every route for the whole game. `(으)로` is form-filling boilerplate a Korean reader associates with a 관공서 document, never with prose. Seeing it inside a narrative sentence reads instantly as unfinished software, and it is the very first sentence the game writes. It also directly contradicts the file's own header rule at ko.ts:10-11 and CLAUDE.md §4a.
- **suggested fix:** This needs a THREE-way rule, not the existing two-way helper: 로 after a vowel, 로 after ㄹ 받침, 으로 otherwise. `endsWithConsonant()` (index.ts:56) cannot express it — it returns true for 물 and would produce `샤워 트레이 고인 물으로`. Add a distinct `{x?으로/로}`-style resolver that special-cases jongseong index 8 (ㄹ), then write `{target}{target?으로/로}` in the four keys. Verify against 거실/욕실/침실 (all ㄹ-final → 로) and 주방 (→ 으로).

### [HIGH] log.threat.incoming produces ungrammatical Korean for 4 of the 7 threats
- **evidence:** ko.ts:238 `'{region}에 {threat}{threat?이/가} 온다.'` combined with the seven labelKeys at src/colony/household.ts:72-132. Rendered output: `주방에 불이 켜짐이 온다.` · `주방에 행주질이 온다.` · `주방에 물건 치우기가 온다.` · `주방에 발소리가 온다.` Only 끈끈이 / 로봇청소기 / 살충제 produce natural sentences.
- **why it costs the player:** This is the `danger` severity line (household.ts:334) — the one the player must parse in under a second while deciding whether to run. `불이 켜짐이 온다` is not a sentence a Korean speaker can produce; a light being switched on does not 'come'. The template assumes every threat name is a physical object, but four of seven are 동사의 명사형. The player loses the one line that is supposed to buy them reaction time.
- **suggested fix:** Split the template by threat type. Give each threat a full predicate key instead of a bare noun — e.g. threat.light → `주방에 불이 켜진다`, threat.wipe → `주방을 행주로 닦는다`, threat.move → `거실 물건을 치우기 시작한다`, threat.footsteps → `주방 쪽으로 발소리가 다가온다` — and keep `{region}에 {threat}{threat?이/가} 온다` only for the three object threats, or drop it entirely.

### [HIGH] WebGL2 failure shows the wrong Korean and tells the player to press a key that does nothing
- **evidence:** src/game/boot.ts:384-386 renders only `t('error.runtime')` = '문제가 생겼다. R을 눌러 다시 시작해라.' There is no WebGL2 capability check anywhere in src (grep for webgl in boot.ts returns only comments). ko.ts:303 `'error.webgl': '이 브라우저에서는 3D 화면을 켤 수 없다. WebGL2를 켜고 다시 열어라.'` is never referenced by any file. Ordering: createRenderer is at boot.ts:88, requestAnimationFrame(tick) is at boot.ts:324 — so a renderer construction failure means the frame loop that drains the input queue never starts, and R is inert.
- **why it costs the player:** A player on a machine without WebGL2 gets a message that misdiagnoses the problem AND instructs an action that cannot work. They press R, nothing happens, they press it again, they leave. The correct sentence — which tells them exactly what to do — was written and then orphaned. This is the failure path where clear Korean matters most, because the player has no other information.
- **suggested fix:** Probe `canvas.getContext('webgl2')` before constructing the renderer and render `t('error.webgl')` on null. Separately, drop 'R을 눌러 다시 시작해라' from error.runtime unless the input loop is provably live at that point — say '새로 고침해라' instead.

### [HIGH] All seven route-health strings are authored and never shown — the player is never told why a route failed
- **evidence:** ko.ts:260-266 defines hud.routeHealth.ok / incomplete / disconnected / blocked / congested / compromised / washed ('양 끝이 붙지 않았다', '끊김', '먹이가 떨어졌다', '통로가 막혔다', '들킨 길', '쓸려 나갔다'). `grep -rn 'routeHealth' src --exclude ko.ts` returns 0 hits. hud.ts has no route panel at all; the HUD is objective / stores / regions / prompt / log only (hud.ts:94-101). `hud.routes` ('페로몬 길', ko.ts:252) is likewise dead.

### [MEDIUM] Household routine names are 명사화 stacks that produce stiff or wrong sentences
- **evidence:** ko.ts:198-203 feed ko.ts:237 `'{routine}{routine?이/가} 곧 시작된다.'`. Rendered: `머리맡 휴대폰이 곧 시작된다.` · `복도 통행이 곧 시작된다.` · `욕실 사용이 곧 시작된다.` · `TV 시청이 곧 시작된다.` Only 설거지가 / 늦은 식사가 read naturally.
- **why it costs the player:** '머리맡 휴대폰이 곧 시작된다' is ungrammatical — a phone does not begin. '복도 통행' and '욕실 사용' are the 한자어 명사 나열 register of a building notice, not of a tense night-time game, and CLAUDE.md §4 explicitly bans long noun stacks. These fire on the `warn` channel to warn the player a human is about to move; stiff bureaucratic Korean blunts the urgency the line exists to create.
- **suggested fix:** Make the routine labels verb phrases and change the template to '{routine}. 곧 시작된다.' — 설거지를 시작한다 / 늦은 식사 / TV를 켠다 / 욕실에 들어간다 / 머리맡에서 휴대폰을 본다 / 복도를 지나간다. Or keep the nouns and change the predicate to '곧 있다'.

### [MEDIUM] Terminology drift: the control list uses '통로 작업' but the world text uses '갉다', and CLAUDE.md's glossary terms 노출 and 대피 appear nowhere
- **evidence:** ko.ts:275 `'help.interact': 'E — 거점 차지 · 통로 작업'` vs the gate descriptions that describe the same action as gnawing: '이걸 갉아 내면' (ko.ts:138), '갉아 내야 한다' (ko.ts:141), '문풍지를 갉는 동안' (ko.ts:150). ### [MEDIUM] There is no i18n test of any kind, despite the source claiming one exists
- **evidence:** src/i18n/index.ts:26-28: 'Exposed so a unit test can assert it is empty after exercising every screen, which is the only way a missing string gets caught before a player sees a raw key.' tests/unit contains house.test.ts, occlusion.test.ts, profiler.test.ts, run.test.ts — `grep -rn 'MISSING_KEYS\|i18n\|locale' tests scripts` returns exactly one hit, a console.log label in scripts/capture.mjs:78. hud.ts:12-15 makes a stronger claim: 'there is no string in the simulation that could reach a player untranslated… which is the defect this project shipped once before'.
- **why it costs the player:** The structural guarantee the author is proud of covers the wrong failure. ## Independent gameplay critic — simulation, economy, progression, pacing (branch experiment/whole-home-infestation-3d) — **FAIL**

I drove the shipped simulation with a public-API-only bot (a near-copy of tests/bot.ts with instrumentation) and cross-checked the world data statically. The systems the design leans on are largely not connected. Measured on the author's own seed/build (20260805, brood): the run is WON in 6.4 minutes against a 25-35 minute target; all five gates open inside 3.5 minutes; the first delivery lands at 4.5 s (design says ~60 s); 452 deliveries produce a peak alert level of 1 out of 4 in every region, so four of the seven household responses can never fire; and victory triggers the moment the fourth region gets a foothold, because every non-region victory condition (12 workers / 30 food / 20 moisture / 1 adaptation) is strictly dominated by the bedroom gate's own requirement (now 22 workers / 96 food / 64 moisture / adaptation) that immediately precedes it. There is no finale — the win screen tells the player they withstood an extermination that statistically never happened. Structurally: five routine ids referenced by the world do not exist, leaving the bedroom (the climactic region) with zero dynamic light, zero dynamic exposure and zero refilling sources, and deleting the bathroom's defining hazard; 13 of 50 authored exposure zones are mathematically inert, including every cover zone in the hallway and the bedroom, so the hallway's "fast route vs safe route" mechanic — which GAUNTLET_STATE claims was fixed — is still half dead; six authored traversal links can never be used by a worker; and run.threats is not rendered by any view module, so a 900-second lethal glue trap is an invisible circle on the floor. The author's account understates the pacing gap by roughly 3.5x and describes an endgame that does not exist. NOTE: the working tree was being edited by another agent while I measured (git diff shows gate costs raised mid-session), so my timing figures are a snapshot; every structural finding below was re-verified against the tree as it stands and is independent of tuning. Two controls I wanted (bathroom taken-vs-skipped, and a routing exposure-weight A/B) did not finish inside my time budget — my harness's replan cost blows up late-game — so the bathroom verdict below is argued from the data, not from a paired run.

### [BLOCKER] Victory is auto-granted by the bedroom gate — the finale never runs
- **evidence:** src/colony/progression.ts:409-421 requires 4 regions + 1 adaptation + population>=12 + food>=30 + moisture>=20. src/world/house.ts:195-200 (bedroom gate) already requires workers 22, food 96, moisture 64, adaptation 'any'. Meanwhile src/i18n/ko.ts:289 tells the winner '박멸 시도를 견뎌 냈다' (you withstood the extermination attempt).
- **why it costs the player:** The climax of a 15-20 minute run is a bookkeeping side-effect of a door the player already opened. They press E on a bedroom foothold and the game says 'you survived the extermination' about an event that did not occur.
